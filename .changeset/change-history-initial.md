Initial release of the change history plugin: entities, options with validation, automatic capture of the catalogue (products, variants, collections incl. moves and their contents per product with one collection-rules batch per run, facets, facet values, assets, promotions and channel assignments — created / updated with before → after values / deleted, cascaded deletions derived from their cause, option groups, manual stock adjustments, derived changes of a product save, actors incl. API keys and the collection rules), the `ChangeHistoryService` facade (`capture` for every core catalogue type, `recordAction`, `recordRun` with detail rows grouped by their parent product, `runBatch`, `reseedCollectionMembership`, and the unstable read helpers `list`, `entityHistory`, `filterOptions`, `runDetails`, `runsForEntity`, `runDetailsForEntity`), tiered retention in `ChangeHistoryRetentionService` (`compact` archives to the archive storage and verifies before it strips or deletes anything, `purge` deletes compacted entries only, `preview`, `restore`) with two built-in scheduled tasks or `retention.schedule: false` for your own scheduler, the before-state and archive storage strategies, the Admin API read queries behind the new `ReadChangeHistory` permission (`changeHistoryEntries` — the feed, derived entries left out by default, with `derivedCount`, `batchCounts`, `entityDeleted`, `isCompacted`, `derivedEntries` and `batchMembers` per entry —, `changeHistoryEntry`, `changeHistoryEntityTimeline` keyset-paged from the primary database with one item per run carrying the entity's rows, `changeHistoryRunDetails` with current labels sorted by SKU, and `changeHistoryFilterOptions`), and a dashboard feed with a `./dashboard` entry for host registrations.
